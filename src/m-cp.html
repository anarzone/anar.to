        A word starts as Learning. Each time you remember it on the due day, the gap grows.

        Decisions behind it

        • Practice pays $0. Drilling words that aren't due would be a farming loop, not learning.
        • No idle income. The café earns nothing while the app is closed. Only learning money waits at the door.
        • Recognising isn't knowing. A word only counts as Known after you've recalled it from the meaning at least once.
        • A wrong answer weakens, it doesn't reset. The word drops into relearning instead of back to new.
        • Ruhetag. One automatic rest day a week keeps your streak, like a Viennese café. Curiosity, not guilt.
        • Staff stay slower than you. Otherwise the café plays itself and gets boring.

        • Every answer runs in one database transaction with the user and session rows locked. The answer's event id makes a retried request harmless.
        • Each answer is stored as an immutable review event with the memory state before and after.
        • The scheduler is FSRS-6, checked against the reference py-fsrs: 0 mismatches over 2,478 reviews.
        • An answer only moves the schedule when the word was due or new. Anything else is stored as practice.
        • There is one balance and the server owns it. The café shows it; café earnings are capped at $400 a minute.

        Curiplay is in development. The words, money rules, star thresholds, prices and intervals come from its code (the intervals from its scheduler test: answering on the due day, no fuzz).
